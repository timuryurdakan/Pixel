# Pixel Office v3 — "Ajan Kontrol Merkezi" (Agent Control Center), trial edition

Status: **v3 design, Phase 11 (2026-10-16); Phase 12 (relay) and Phase 13 (connector) implemented 2026-10-17, Phase 14 (UI) and Phase 15 (security review, QA, docs) 2026-10-19 — code complete, deployment pending (README "Yayına alma kontrol listesi (v3)"), see §20.** This is the binding contract for Phases 12–15, in the same way that
`docs/ARCHITECTURE.md` was for v1 and `docs/CLOUD.md` was for v2. If you must deviate, update this file (add a
"Phase N deviations" subsection to §20) and log it in `PROJECT.md` → İlerleme Günlüğü.

**v1 and v2 keep working unchanged.** `python3 server.py [--demo]`, `python3 dev_server.py [--demo]`, every endpoint in
ARCHITECTURE.md and CLOUD.md, the hook clients, `pixel_agent.py`, the PWA and the mini window behave as before. v3 only
adds files, adds optional fields and adds one Vercel endpoint. A deployment without the v3 environment variables
(`RELAY_SECRET`, `PIXEL_RELAY_URL`) behaves exactly like v2: `/api/config` reports `"relay": null` and the UI hides every
v3 control.

Hard constraints (inherited, still binding):
- Free tiers only, no credit card: Vercel Hobby, Upstash Redis free, **Cloudflare Workers Free**.
- No Node.js on the dev machine. No build step for `web/`. No CDN or npm dependencies in the browser.
- Python stdlib only for everything that runs on a user's machine and on Vercel.
- Browser crypto = **WebCrypto only** (no JS crypto code).
- UI text is Turkish. Code, identifiers and this document are English.

Scope (exactly these six items): connector app (§5), prompt box (§11.2), live status and token counter (§10, §11.3),
phone remote control (§9, §11.5), security (§6, §7), realtime relay (§4). **Out of scope:** automation templates and
multi-agent pipelines (postponed to the separate "v4 — Otomasyonlar" study), sharing your agents with other room
members, Web Push notifications, and prompting from the v1 local mode (§1.3).

## 0. Decisions at a glance

| Topic | Decision | Why (short) |
|---|---|---|
| Realtime relay | **Cloudflare Worker + one SQLite-backed Durable Object per room, WebSocket Hibernation API** (`relay/`) | Durable Objects are on the Free plan (SQLite backend only): 100K requests/day, 13,000 GB-s/day. Incoming WS messages are billed 20:1, outgoing messages are free, and hibernated sockets cost no duration. The 5-user load uses about 8% of requests and at most about 35% of duration (§15). |
| Relay language | **JavaScript ES module, zero npm runtime dependencies**. `wrangler` is a devDependency used only by Cloudflare's build. | Python Workers need `uv` + Node locally for `pywrangler` (§21 [S7]), and the Durable Object WebSocket examples are JS-first. |
| Build/deploy | **Cloudflare Workers Builds** connected to `github.com/timuryurdakan/Pixel`, root dir `relay/`, build `npm install && npm test`, deploy `npx wrangler deploy` | Cloudflare builds in its own image (Node 22/24 preinstalled). Free: 3,000 build minutes/month, 1 concurrent build. |
| Node on the dev machine | **Not required.** Local tests run against `tools/dev_relay.py`, a stdlib Python implementation of the same relay protocol. A shared conformance suite runs against both it and the deployed Worker. The Worker's pure logic is unit-tested with `node:test` inside Workers Builds, and a failing test blocks the deploy. | The user does not need `sudo apt install nodejs npm`. That command stays an optional extra for anyone who wants `wrangler dev` (§16.4). |
| Relay auth | Vercel mints **short-lived relay tickets** (`POST /api/relay_ticket`, write key required), HMAC-SHA256 with **`RELAY_SECRET`**, which is shared by Vercel and Cloudflare. The ticket is carried in `Sec-WebSocket-Protocol`, never in the URL. | Cloudflare never learns `PIXEL_SECRET`. A ticket costs one Vercel invocation and 0 Redis commands. |
| Device control authority | **Only browsers paired with a device can command it.** Pairing uses a one-time code shown on the device. The room write key alone is not enough. | Friends in the room still see characters but cannot prompt your machine. This also keeps each person on their own Claude account (§18.1). |
| Pairing | One-time 12-character code (4-char rendezvous slot + 40-bit secret). The secret is stretched with **PBKDF2-HMAC-SHA256, 600,000 iterations** and used for mutual key confirmation over P-256 public keys, then confirmed with a 6-digit SAS in the device terminal. One wrong guess burns the code. | Gives MITM resistance against the relay without a PAKE library (§7.3). |
| E2E crypto | **ECDH P-256 + HKDF-SHA256 + AES-256-GCM** (+ PBKDF2, HMAC). Browser: WebCrypto. Connector: **vendored pure-Python implementation** in `pixel_connector/crypto.py`, tested against RFC/NIST/Wycheproof vectors and cross-tested against WebCrypto in headless Chrome. No `cryptography` dependency. | Keeps the connector stdlib-only like every other client. Payloads are small (≤ 64 KiB), so pure-Python speed (~100 KB/s) is enough. P-256 rather than X25519 because WebCrypto X25519 support in Safari is unconfirmed (§7.1). |
| Session security | Per-connection handshake: ephemeral-ephemeral + static-static ECDH (forward secrecy + mutual authentication), direction-separated keys, 64-bit counter nonces, strict replay check | §7.4 |
| Connector | `pixel_connector/` package, distributed as a single stdlib **zipapp** `web/connector/pixel-connector.pyz` (Python ≥ 3.8), runs as a systemd **user** service (Linux first), launchd agent (macOS), Task Scheduler (Windows) | Same distribution model as `web/hook/` |
| Engines | Claude Code via `claude -p --output-format stream-json --verbose --include-partial-messages`, prompt on **stdin**, session continuity with `--session-id` / `--resume`. Ollama via `/api/chat` NDJSON streaming. OpenAI-compatible servers via `/v1/chat/completions` SSE with `stream_options.include_usage`. | §8 |
| Claude Code permissions | Default profile **`edit` = `--permission-mode dontAsk --allowedTools Edit,Write,NotebookEdit`** (reads + edits inside the workspace, no shell apart from the read-only command set). `bypassPermissions` / `--dangerously-skip-permissions` is **never** passed and cannot be configured. `auto` only works if enabled in the device config. | §8.1.3 |
| Remote commands | Only **runtime ids from the device's local allow-list** (`connector.json`). Each id maps to a fixed argv, with no shell and no parameters taken from the cloud. | §9 |
| Content privacy | Prompts, outputs, tool details, workspace paths, runtime names, device names and usage numbers only travel E2E-encrypted. The office character state still goes to Vercel exactly as in v2 (state, tool name, fixed label, project basename, owner), plus one new opaque field `ctl`. | §6.3 |
| Token accounting | Device-side SQLite ledger (`sqlite3` is stdlib). Claude Code: `result.modelUsage` + `total_cost_usd` (client-side *estimates*; delta-corrected on resume). Ollama: `prompt_eval_count` / `eval_count`. Budgets per agent or device, per day/week/month, in tokens or estimated USD. | §10 |
| Local mode (server.py) prompting | **Not in this trial; planned as v3.1.** The protocol is transport-agnostic, and `tools/dev_relay.py` is already the local relay, so v3.1 only needs to mount it in `server.py` (§1.3). | Halves the Phase 14 UI test matrix |
| Resident agents (Mete/Saltuk) | Removed from the room (`POST /api/residents` with `[]`). The code (`pixel_cloud/residents.py`, `api/residents.py`) stays and is not touched by v3. | Owner's decision |

### 1.2 Data paths

| Path | Transport | Content | Encrypted end-to-end? |
|---|---|---|---|
| Office character state (connector agents) | connector → Vercel `POST /api/status` → Upstash → viewers poll `/api/state` | v2 allow-list + `ctl` | no (same privacy as v2) |
| Commands, prompts, streamed output, usage, runtime info | browser ⇄ relay DO ⇄ connector over WebSocket | inner messages §3.4 | **yes** (AES-256-GCM) |
| Relay tickets | browser/connector → Vercel `POST /api/relay_ticket` | room, role, id | TLS only |
| Pairing | browser ⇄ relay ⇄ connector | public keys, nonces, MACs | authenticated, not secret (§7.3) |

### 1.3 Local mode decision

`server.py` (v1 local mode) does **not** get prompting in this trial. Reasons: the trial's users meet in a cloud room
anyway, and the Phase 14 UI would otherwise need a second set of entry flows (no room, no ticket). The design keeps
the door open:
- the relay protocol (§3) is transport-agnostic, and the connector only needs a URL plus a ticket source;
- `tools/dev_relay.py` (Phase 12) implements the full relay in stdlib Python.

v3.1 plan (not part of Phases 12–15): `server.py --relay` mounts `dev_relay` at `ws://127.0.0.1:8765/relay`, issues
loopback tickets without a room key, and the connector config gets `"relay": "local"`. The crypto and the inner
messages stay unchanged.

## 3. Message protocol

Two layers:
- **L1 (relay frames):** cleartext JSON text frames between a client and the relay. The relay parses only L1.
- **L2 (inner messages):** JSON carried inside L1 `send`/`msg` frames as `b` (base64url bytes). Handshake bodies
  (`k: "hs"`) are authenticated but not secret. Everything else (`k: "e"`) is AES-256-GCM ciphertext (§7.5).

Encoding rules (both layers): UTF-8 JSON, no BOM, unknown fields ignored, missing optional fields = null. Integers are
JSON numbers ≤ 2^53. base64url = RFC 4648 §5 without padding. Ids:

| Name | Format | Meaning |
|---|---|---|
| `roomId` | `[a-z2-7]{26}` | v2 room id |
| `deviceId` / `bid` | `[a-z2-7]{16}` = lowercase base32(SHA-256(raw public key, 65 bytes))[:16] (80 bits) | identity of a connector / a browser profile |
| `conn` | `c:` + `[A-Za-z0-9_-]{12}` | one browser WebSocket (one tab), assigned by the relay |
| `slot` | `[0-9A-HJKMNP-TV-Z]{4}` (Crockford base32) | pairing rendezvous |
| `ch` | `[A-Za-z0-9_-]{16}` = base64url(T[:12]) | E2E channel id (§7.4) |
| `agent` key | `[A-Za-z0-9_-]{1,24}` | agent id on a device |
| `task` id | `t_` + `[A-Za-z0-9_-]{10}` | assigned by the device |
| request `id` | `[A-Za-z0-9_-]{1,32}` | chosen by the browser; replies carry `re` |

### 3.1 Connecting

```
GET wss://<relay-host>/v1/rooms/<roomId>/ws
Upgrade: websocket
Sec-WebSocket-Protocol: pixel-relay.v1, tk.<ticket>
Origin: https://pixel-rouge-phi.vercel.app        (browsers; the connector sends no Origin)
```
The Worker:
1. checks the path, verifies the ticket (§6.2), checks that `ticket.r == roomId`;
2. for `role == "browser"`, requires `Origin` ∈ `ALLOWED_ORIGINS`; for `role == "device"`, requires the Origin header to be absent;
3. forwards the request to `env.ROOMS.get(env.ROOMS.idFromName(roomId))`.

The DO accepts with `this.ctx.acceptWebSocket(server, tags)` and answers 101 with `Sec-WebSocket-Protocol: pixel-relay.v1`.
Tags: device → `["dev", "dev:<deviceId>"]`; browser → `["br", "br:<bid>", "conn:<c>"]`. The attachment
(`serializeAttachment`, ≤ 16 KiB) holds `{role, id, conn, since, app, slot?, slotExp?}`.
Failures before the upgrade → HTTP 401 `{"error":"bad_ticket"}`, 403 `{"error":"bad_origin"}`, 404, 429 `room_full`.

WebSocket close codes used by the relay: 1000 normal, 1008 policy (bad frame), 1009 too big,
**4001** ticket expired at reconnect, **4009** replaced (same deviceId connected again), **4029** rate limited.

### 3.2 L1 frames: client → relay

| `t` | Sender | Schema | Notes |
|---|---|---|---|
| `hello` | both | `{"t":"hello","v":1,"app":"connector/3.0.0"\|"web/3.0.0","caps":["e2e1"]}` | Optional but sent by our clients. Stored in the attachment (`app` ≤ 40 chars). Version gate: `v` must be 1. |
| `send` | both | `{"t":"send","to":"<deviceId>"\|"c:<conn>"\|"pair:<slot>","ch":"<ch>"\|null,"seq":<int ≥ 0>,"k":"hs"\|"e","b":"<base64url>"}` | Browsers may address only devices and `pair:` slots. Devices may address only `c:` conns. `b` ≤ 48 KiB decoded for browsers, 60 KiB for devices. |
| `pair.open` | device | `{"t":"pair.open","slot":"K7Q2"}` | Tags the socket `pair:<slot>` and stores `slotExp = now + 600 s` in the attachment. At most 1 slot per device and 4 per room. |
| `pair.close` | device | `{"t":"pair.close","slot":"K7Q2"}` | Also implicit on expiry or disconnect. |
| `presence.get` | browser | `{"t":"presence.get"}` | |
| `ping` | both | exactly `{"t":"ping"}` | Answered by `setWebSocketAutoResponse` with exactly `{"t":"pong"}` (no DO wake-up). The connector prefers protocol-level ping frames every 30 s (not billed). |

### 3.3 L1 frames: relay → client

| `t` | Receiver | Schema |
|---|---|---|
| `welcome` | both | `{"t":"welcome","v":1,"conn":"c:…"\|null,"role":"device"\|"browser","id":"<deviceId\|bid>","serverTime":<ms>,"limits":{"maxFrame":65536,"msgPerSec":20}}` |
| `presence` | browsers | `{"t":"presence","devices":[{"id":"<deviceId>","since":<ms>,"app":"connector/3.0.0"}]}`, sent on connect, on `presence.get`, and when a device connects or disconnects |
| `msg` | both | `{"t":"msg","from":"<deviceId>"\|"c:<conn>","bid":"<bid>"\|null,"ch":…,"seq":…,"k":"hs"\|"e","b":"…"}`. `bid` is the browser id from the sender's ticket (null when from a device). |
| `left` | devices | `{"t":"left","conn":"c:…"}` when a browser socket closes (the device drops that channel) |
| `pair.opened` | device | `{"t":"pair.opened","slot":"K7Q2","exp":<ms>}` |
| `err` | both | `{"t":"err","code":"<code>","ref":<seq\|null>,"message":"<short English>"}`, codes: `bad_frame`, `too_large`, `rate_limited`, `device_offline`, `conn_gone`, `slot_unknown`, `slot_taken`, `slot_limit`, `forbidden`, `version` |

Relay invariants (tested by `relay_conformance.py`):
- The relay never parses `b`, never logs `b`, and never stores frames (no DO storage writes on the message path).
- A frame that fails validation → `err bad_frame` (or close 1008 after 5 bad frames in 60 s).
- `send` to an offline target → `err device_offline` / `conn_gone` with `ref = seq`. **No queueing.**
- Fan-out: never. Every `send` goes to exactly one socket (a `pair:` slot resolves to the device that opened it).

### 3.4 L2 inner messages

Every inner message is a JSON object with `type`. Requests from the browser may carry `id`; the device's replies
carry `re` with the same value. All inner messages travel E2E-encrypted (`k: "e"`) except the handshake (§7.3, §7.4).

**Browser → device**

| `type` | Fields | Reply |
|---|---|---|
| `peer.hello` | `label` (≤ 40, e.g. "Chrome · Linux", "Telefon"), `app` | `device.info` |
| `agent.list` | — | `agent.list.result {agents:[Agent]}` |
| `agent.create` | `name` (1–24), `engine` ∈ `claude`\|`ollama`\|`openai`, `model` (≤ 64 or null), `workspace` `{id, sub}` (`sub` relative path ≤ 200 or null), `profile` ∈ `readonly`\|`edit`\|`dev`\|`auto`, `budget` (Budget without `scope`, or null) | `agent.created {agent}` |
| `agent.update` | `agent`, any of `name`, `model`, `profile`, `budget` | `agent.updated {agent}` |
| `agent.delete` | `agent` | `agent.deleted {agent}` (the character leaves: `offline`) |
| `agent.reset` | `agent` | starts a new Claude session / clears Ollama history → `agent.updated` |
| `agent.watch` | `agent`, `on` (bool) | none; while on, this channel receives `task.*` events of that agent even if another browser started the task |
| `workspace.list` | — | `workspace.list.result {workspaces:[{id, name, children:[name…] (≤ 50, depth 1) \| null}]}` |
| `task.start` | `agent`, `prompt` (1..32768 bytes UTF-8), `fresh` (bool, default false) | `task.ack` then `task.chunk*`, `task.end` |

### 3.5 Flow control and sizes

- The connector coalesces `task.chunk` parts: flush when **250 ms** have passed since the first unflushed part, or when the
  buffered plaintext reaches 8 KiB, or at task end. At most 4 chunks/s per task. This is the main lever for the DO request budget (§15).
- Inner plaintext ≤ 56 KiB after padding (one frame). Bigger results (`task.end.result`, `task.get.result`) are truncated to
  64 KiB of UTF-8 with `"truncated": true`. The full text stays in the device ledger.
- Browser request timeout: 15 s for request/response types (UI shows "Cihaz yanıt vermedi"). Tasks have no browser timeout;
  the device enforces `limits.taskTimeoutS` (default 3600).

## 4. Realtime relay (Cloudflare Worker + Durable Object)

### 4.1 Choice and alternatives (researched 2026-10-16, sources §21)

| Option | Free-tier facts | Verdict |
|---|---|---|
| **Cloudflare Workers Free + Durable Objects (SQLite) + WebSocket Hibernation** | Workers: 100,000 requests/day, 10 ms CPU per HTTP request [S2]. Durable Objects are **available on Free, SQLite backend only**: 100,000 requests/day, 13,000 GB-s/day, 5M rows read, 100K rows written, 5 GB stored. Exceeding a limit makes those operations fail, with a reset at 00:00 UTC [S1]. A WS connection = 1 request, **incoming WS messages billed 20:1, outgoing messages free**, protocol pings free, and hibernated or hibernation-eligible idle objects accrue no duration [S1]. Up to 32,768 WS per object [S4]. Received message ≤ 32 MiB [S3]. | ✅ **Chosen.** Push in both directions and nothing to run ourselves. Comfortably inside the limits for 5 users (§15). |
| Polling Upstash from connector and browser | 500K commands/month total, of which v2 alone already uses ≈ 53% for 5 users (§15.3) | ❌ Even a 2 s poll from 8 devices is 345K commands/month before any streaming |
| Vercel functions holding SSE/WS | WebSockets not supported. SSE holds a function instance for its whole lifetime (CLOUD.md §4.1) | ❌ |
| Supabase Realtime | 200 concurrent connections, 2M messages, but **pauses after 7 days idle**, and the client is an npm library | ❌ More moving parts, plus the pause |
| Cloudflare Python Worker | Durable Objects reachable, but deployment needs `uv` + Node + `pywrangler` locally [S7] | ❌ Doesn't remove Node, and the WS Hibernation examples are JS |
| Self-hosted relay (home server, VPS) | Costs money or needs a public IP | ❌ |

### 4.3 Durable Object `RoomRelay` (`relay/src/room.js`)

- `fetch(req)`: read claims, enforce room limits (≤ **8** device sockets, ≤ **24** browser sockets → 429 `room_full`), create
  a `WebSocketPair`, `ctx.acceptWebSocket(server, tags)`, `server.serializeAttachment({...})`, send `welcome` (+ `presence` to
  browsers), and if a device with the same id is already connected, close the old socket with 4009. Notify browsers with `presence`.
- Constructor: `ctx.setWebSocketAutoResponse(new WebSocketRequestResponsePair('{"t":"ping"}','{"t":"pong"}'))`. **No alarms, no
  `setTimeout`/`setInterval`** (they prevent hibernation [S3]). Rate-limit buckets live in an in-memory `Map` keyed by conn.
  They reset when the object hibernates, which is acceptable best-effort behaviour.
- `webSocketMessage(ws, data)`: size check (`typeof data === 'string'`, ≤ 64 KiB, else close 1009); `JSON.parse`; validate with
  `lib.validateFrame(frame, role)`; token bucket per socket (devices 20 msg/s burst 100; browsers 5 msg/s burst 30; pairing sends
  3/min per browser conn) → `err rate_limited`; dispatch:
  - `send` → resolve the target: `ctx.getWebSockets('dev:'+to)[0]` / `('conn:'+c)[0]` / `('pair:'+slot)[0]` (checking `slotExp`
    from the attachment, and that the sender is a browser) → `target.send(JSON.stringify({t:'msg', from, bid, ch, seq, k, b}))`.
  - `pair.open` / `pair.close` → slot tag bookkeeping. Tags are fixed at accept time, so a slot is stored in the attachment and
    looked up by scanning `getWebSockets('dev')` (≤ 8 sockets). This is cheap and avoids storage.
  - `presence.get` → reply.
- `webSocketClose` / `webSocketError`: if it was a device → `presence` to all browsers; if it was a browser → `left` to all devices.
- **No storage use at all** on the hot path (0 rows written). If Phase 12 needs persistence (it shouldn't), use SQLite only.

### 4.4 `tools/dev_relay.py` (local, stdlib)

Same URL shape (`ws://127.0.0.1:8788/v1/rooms/<rid>/ws`), the same ticket verification (`RELAY_SECRET` env), the same frames,
limits, close codes and error codes, and the same auto-response. Threaded server built on `socketserver.ThreadingTCPServer`
plus `pixel_connector/ws.py` server-side framing. `python3 dev_server.py --relay` starts it on port 8788, generates a random

**Contract:** `tests/relay_conformance.py` must pass unchanged against `dev_relay` and against the deployed Worker.

## 5. Connector app (`pixel_connector`)

### 5.1 Runtime model

One long-running process per machine (`pixel-connector run`, normally under the service manager). Python ≥ 3.8, stdlib only,
threads (no asyncio requirement; asyncio allowed if it stays 3.8-compatible). Components:

```
relay thread ──► session.Router ──► per-channel decrypt ──► dispatcher ──► tasks.Scheduler ──► engine worker threads
     ▲                                                          │                 │
     └──────────── encrypt + L1 send ◄── outbound queue ◄───────┴── usage.Ledger ◄┘   agents.Reporter → /api/status
```

- **Room binding:** one connector = one room (from `connector.json`: `server`, `room`, `key`, `owner`). The key is the v2 room
  write key, used for `/api/relay_ticket` and `/api/status`.
- **Reconnect:** fresh ticket per attempt, backoff 1 → 30 s with jitter; after 10 consecutive failures, 5 min. Protocol ping every 30 s, and the connection is treated as dead after 75 s without any frame.
- **Agents in the office:** each connector agent reports through the bundled `pixel_agent.Sender` (v2 coalescing rules, CLOUD.md
  §17.2) with `session = "c_" + agentKey`, `source = "connector"`, `project = workspace.name`, `name = agent.name`,
  `ctl = deviceId + "." + agentKey`. Mapping: task start → `thinking`; `tool` part → `working` + tool name; confirmation pending →
  `waiting_for_user` label "Onay bekliyor"; end → `idle` label "Görev bitti" / "Hata" / "Durduruldu". Keep-alive: while the connector
  runs, re-send each agent's current state every **20 min**, so v2's 45-minute removal never triggers (idle agents go to sleep as in
  v2 and stay in the beds). On shutdown or `agent.delete` → `offline`.
- **No duplicate characters:** child processes get `PIXEL_OFFICE_DISABLE=1`, so a user-installed v2 hook (`pixel_hook.py`) ignores
  sessions started by the connector.
- **Single instance:** a lock file `~/.pixel-office/connector/run.lock` (`fcntl.flock` / `msvcrt.locking`).

## 6. Security model

### 6.1 Principles

1. **The device is the authority.** Every decision about what may run is made on the device from local files: paired peers,
   workspace allow-list, permission profiles, runtime allow-list, budgets, rate limits, confirmation. The cloud carries requests
   but cannot widen any of these.
2. **No arbitrary execution from the cloud.** The only processes the connector starts are (a) the configured engine binary with an
   argv built from fixed templates, and (b) runtime argv lists copied verbatim from `connector.json`. No shell, no string
   interpolation, no environment variables from requests.
3. **E2E for content.** The relay and Vercel never see content (§1.2).
4. **Least privilege by default.** Claude Code profile `edit`, no Bash. `auto` is opt-in on the device. `bypassPermissions` is impossible.
5. **Everything is auditable locally.**

### 6.2 Authentication to the relay

**Ticket minting (Vercel, Phase 12):** `POST /api/relay_ticket?room=<rid>`, `Authorization: Bearer <writeKey>` (v2 HMAC write key,
checked with `ids.check_write_key`), body ≤ 256 B: `{"role":"browser"|"device","id":"<16 base32>"}`.
Response `200`:
```json
{"url":"wss://pixel-relay.<sub>.workers.dev/v1/rooms/<rid>/ws","ticket":"v1.<payload>.<mac>","exp":1792100120}
```
- `payload` = base64url(JSON `{"r":"<rid>","ro":"browser"|"device","id":"<id>","iat":<unix s>,"exp":<iat+120>,"n":"<8 random bytes b64url>"}`)
- `mac` = base64url(HMAC-SHA256(`RELAY_SECRET`, `"pixel-relay-ticket:v1:" + payload`)) (full 32 bytes)
- Errors: 401 (key), 404 (room format), 400 (body), 429 (per room 30/min, per IP 30/min, in-process), 503 `relay_not_configured`.
- `Cache-Control: no-store`. **0 Redis commands.** The ticket and body are never logged.

**Verification (Worker `lib.verifyTicket`, same in `dev_relay.py`):** exactly three dot-separated parts with prefix `v1`;
HMAC check with `crypto.subtle.verify` (constant time); `iat ≤ now + 30`, `exp ≥ now`, `exp − iat ≤ 120`; `r` matches the path; `ro`/`id`
formats. Clock source: the Worker's `Date.now()`. Tickets are not single-use. They are short-lived, room/role/id-scoped and never
appear in URLs, so a replay within 120 s only gives the same access the holder of the write key already has.

**Secret:** `RELAY_SECRET` = `python3 -c "import secrets;print(secrets.token_urlsafe(32))"` (43 chars). It is set **identically**
in Vercel (Production env var) and in the Worker (Secret). It is independent of `PIXEL_SECRET`, so a Cloudflare compromise cannot
forge v2 write keys. Rotation: change it in both places. Open sockets keep working until they reconnect, then pick up new tickets
automatically (no re-pairing needed).

**Origin check:** browser tickets are accepted only with `Origin` ∈ `ALLOWED_ORIGINS` (protects against cross-site WebSocket
hijacking with a stolen ticket in someone else's page). Device tickets must have no `Origin`.

**Vercel ↔ relay:** Vercel never calls the relay, and the relay never calls Vercel or Upstash. The only shared state is `RELAY_SECRET`.
`/api/health` does not probe the relay (the UI shows the relay status from its own connection attempt).

### 6.3 What each party learns

| Party | Learns | Never learns |
|---|---|---|
| Relay (Cloudflare) | room ids, device ids, browser ids, connection IPs/times, `app` strings, frame sizes (padded to 64 B), message timing/direction, pairing slots | prompts, outputs, tool calls, paths, device names, runtime names, usage, budgets, agent names |
| Vercel/Upstash | v2 data + `ctl` (device id + agent key) for connector agents; ticket requests (room, role, id) | everything E2E |
| Other room members | the characters (v2), that an agent is controllable (`control` field), and device presence if they open a relay connection | content; they cannot command (not paired) |

### 6.4 Workspace allow-list (`workspaces.py`)

- `connector.json → workspaces: [{id, name, path, children}]`. `path` is expanded (`~`, env vars are **not** expanded), then
  `os.path.realpath`. `children: true` lets `agent.create` pick a direct or nested subdirectory via `sub`.
- Resolution of `{id, sub}`: `base = realpath(ws.path)`; if `sub` → reject absolute paths, `..` components, NUL, drive letters and
  UNC paths; `cand = realpath(join(base, sub))`; require `os.path.commonpath([base, cand]) == base` (case-folded on macOS/Windows);
  require `isdir(cand)`. Symlinks are resolved before the check, so a symlink pointing out of the workspace is rejected.
- Built-in deny list (always, even if configured): the home directory itself, `/`, `~/.ssh`, `~/.gnupg`, `~/.aws`, `~/.config`,
  `~/.pixel-office`, `~/.claude`, `/etc`, `/usr`, `/bin`, `/sbin`, `/System`, `C:\Windows`, `C:\Program Files*`. Any workspace equal to or
  under a denied path fails `config-check`.
- Re-resolved at **every** task start (the directory may have been replaced by a symlink in the meantime).
- The browser only ever sees `id`, `name` and child names, never absolute paths.

### 6.6 Optional confirmation on the device (`approvals.py`)

`connector.json → confirm: {"task": "never"|"always"|"new_session", "agentCreate": true|false, "runtime": true|false, "peerRevoke": true|false, "timeoutS": 120}`.
Defaults: `task: "never"`, `agentCreate: false`, `runtime: false`, `peerRevoke: false`. Recommended when you use the `auto` profile: `task: "always"`.
When a confirmation is needed:
1. the device sends `task.ack {confirm:"pending"}` (or `confirm.result` later) and reports `waiting_for_user` to the office;
2. it notifies locally: Linux `notify-send` (if present), macOS `osascript -e 'display notification …'`, Windows a PowerShell toast; the text
   is fixed ("Pixel Office: <ajan adı> için onay bekleniyor") and never includes the prompt;
3. the user approves at `http://127.0.0.1:8766/onay` (lists pending items with the prompt preview, buttons **Onayla** / **Reddet**,
   protected by the control token in a same-origin cookie plus a CSRF token, `Host` check) or with `pixel-connector approve <id>`;
4. timeout → `task.end {status:"denied", error:{code:"confirm_timeout"}}`.

### 6.7 Audit log (`audit.py`)

JSON Lines, one object per security-relevant event. Rotated at 5 MB, 3 files kept. Never sent anywhere.
```json
{"ts":"2026-10-16T14:03:22.114+03:00","ev":"task.start","bid":"k3…","peer":"Telefon","agent":"a1","engine":"claude",
 "ws":"pixel","sub":null,"profile":"edit","promptSha256":"9f2c…","promptLen":412,"result":"ok","task":"t_AbC…"}
```
Events: `pair.ok`, `pair.fail` (reason), `peer.revoke`, `hs.ok`, `hs.fail`, `tamper`, `task.start`, `task.end` (status, tokens,

### 6.8 Revocation

- From the device: `pixel-connector peers revoke <bid>` (or `revoke-all`) → peer marked revoked, its open channels closed, and further
  `hs1` from that bid rejected.
- From any paired browser: `peer.revoke {bid}`, so a lost phone can be revoked from the desktop. The device asks for local
  confirmation if `confirm.peerRevoke` is true (default false). Revoking yourself = "Bu tarayıcının eşleşmesini kaldır".
- Whole device: `reset-keys` (new identity) or `uninstall-service` + delete `~/.pixel-office/connector/`.
- Room-level: as in v2, a leaked join link means creating a new room (CLOUD.md §3.1). Devices then need `setup` with the new room,
  but **pairings survive** (they are keyed by device/browser identity, not by room).

## 7. End-to-end encryption

### 7.1 Algorithm choice

| Primitive | Browser (WebCrypto) | Connector (`crypto.py`, pure Python) | Test vectors |
|---|---|---|---|
| Key agreement | `ECDH`, `namedCurve: "P-256"`, `deriveBits(…, 256)` | P-256 scalar multiplication (Jacobian coordinates, fixed 256-step Montgomery ladder), SEC1 uncompressed point encode/decode **with full validation** (length 65, prefix 0x04, 0 ≤ x,y < p, on curve; cofactor 1), shared secret = 32-byte big-endian x-coordinate | RFC 5903 §8.1; NIST CAVP ECC CDH P-256 (25 vectors); Wycheproof `ecdh_secp256r1_ecpoint_test.json` (invalid points must be rejected) |
| KDF | `HKDF` with `SHA-256` | RFC 5869 via `hmac` + `hashlib` | RFC 5869 A.1–A.3 |
| Code stretching | `PBKDF2` with `SHA-256` | `hashlib.pbkdf2_hmac('sha256', …)` (stdlib) | RFC 7914 §11 PBKDF2-HMAC-SHA256 vectors |
| MAC | `HMAC` with `SHA-256` | `hmac` | RFC 4231 |
| AEAD | `AES-GCM`, 256-bit key, 96-bit IV, 128-bit tag | AES-256 (FIPS-197) + GCM (SP 800-38D): CTR with inc32, GHASH by bitwise GF(2^128) multiply (no key-dependent tables), constant-time tag compare (`hmac.compare_digest`) | NIST GCM test vectors (256-bit key, 96-bit IV subset), Wycheproof `aes_gcm_test.json` (keySize 256, ivSize 96, including invalid tags) |
| Random | `crypto.getRandomValues` | `secrets.token_bytes`, `secrets.randbelow` | — |

**Why pure Python (decision):**
- *`cryptography` via pip* would be fast and audited, but it breaks the project's "stdlib-only client" promise. On Debian/Ubuntu,
  `pip install --user` is blocked by PEP 668, so users need `apt install python3-cryptography` or a venv. On Windows it is another
  install step for friends. Rejected for the trial.
- *Another scheme from stdlib only* (an HMAC-SHA256 keystream with encrypt-then-MAC plus a pre-shared secret from the pairing code)
  would avoid AES but is a custom construction, has no forward secrecy and still needs key agreement. Rejected.
- *Vendored pure-Python P-256 + AES-GCM*, ≈ 450 lines with ≈ 300 test vectors plus live cross-tests against WebCrypto, is
  well-specified and standard, and the browser side stays 100% native WebCrypto. **Chosen.**

Known limits, accepted and documented:
- Pure-Python big-integer and S-box operations are not constant-time. An attacker who can time the connector process precisely
  (same machine) could in theory learn key bits. Remote timing through the relay is drowned by network jitter and CPython overhead,
  and a local attacker on the device already defeats the model (§14).
- Speed: AES-GCM ≈ 100–200 KB/s and P-256 ECDH ≈ 30–80 ms per operation in CPython. Fine for ≤ 4 chunks/s of ≤ 8 KiB and one handshake per connection.

P-256 rather than X25519: WebCrypto X25519 shipped in Chrome 133 and Firefox 130, but the Safari/iOS version could not be confirmed
(§21 [S12]). The phone is a primary client, so universally supported P-256 wins. The `v` fields allow adding X25519 later.

### 7.2 Keys and storage

| Key | Where | Lifetime |
|---|---|---|
| Device static key `(dC, QC)` | `keys.json` (0600), private scalar in hex | until `reset-keys` |
| Browser static key `(dB, QB)` | IndexedDB `pixel-office` → store `e2e` → `"browserKey"`: a `CryptoKeyPair` generated with **`extractable: false`** for the private key (`['deriveBits']`). The public key is exported raw (65 bytes) once and stored next to it. | per browser profile (one per origin, shared by all rooms) |
| Paired devices (browser side) | IndexedDB store `devices`: `{deviceId, pub, name, pairedAt, room}` | until removed |
| Paired browsers (device side) | `peers.json` | until revoked |
| Session keys | memory only (browser: non-extractable `CryptoKey` AES-GCM; Python: bytes) | one WebSocket connection, max 24 h, or 2^32 messages per direction |

iOS note: Safari may evict IndexedDB for sites not added to the home screen after 7 days without use. The installed PWA keeps its
storage. If evicted, the user pairs again (the UI says so: "Bu tarayıcının anahtarı bulunamadı, cihazı yeniden eşleştirin").

### 7.3 Pairing protocol

Code format: 12 Crockford-base32 characters shown as `K7Q2-M4X5-Z6A9`. Characters 1–4 = `slot` (rendezvous, visible to the
relay). Characters 5–12 = `secret` (40 bits, **never sent anywhere**). Input normalisation: uppercase, `O→0`, `I/L→1`, strip `-` and spaces.
The code is valid for **10 minutes** and for **one attempt**.

```
 Device (connector)                         Relay (DO)                         Browser (e2e.js)
 user runs `pixel-connector pair`
 slot,secret ← random; nC ← 16 B
 ── L1 pair.open {slot} ─────────────────────► tag socket pair:<slot>, exp 600 s
 prints  "Kod: K7Q2-M4X5-Z6A9 (10 dk geçerli)"
                                                                         user types the code in "Cihaz ekle"
                                                                         K ← PBKDF2-SHA256(secret, salt="pixel-pair-v1|"+slot, 600000, 32 B)
                                                                         nB ← 16 B; QB = browser static pub
                                              ◄──── send to "pair:<slot>" k=hs  {"t":"pair1","v":1,"slot","qB","nB"}
 ◄── msg from c:<conn> (bid from ticket) ──────
 check: slot open, bid == id(qB), qB valid point
 ── send to c:<conn> k=hs {"t":"pair2","v":1,"deviceId","qC","nC"} ────────────────────────────────►
                                                                         check deviceId == id(qC), qC valid
                                                                         T = SHA-256("pixel-pair-v1" ‖ slot ‖ deviceId ‖ bid ‖ qC ‖ qB ‖ nC ‖ nB)
                                                                         macB = HMAC(K, "B" ‖ T)
                                                                         SAS = (uint32_be(HMAC(K, "SAS" ‖ T)[0:4]) mod 10^6) → "482 913"
                                                                         shows: "Terminalde 482 913 görünüyorsa orada onaylayın"
 ◄────────────────────────────────────────────── send k=hs {"t":"pair3","macB"}
 K ← PBKDF2(…) (same); T (same, own view)
 verify macB (constant time)   ── fail → burn slot, pair.close, audit pair.fail, print "Kod yanlış ya da araya girildi. Yeni kod üretin."
 burn slot (pair.close) — one attempt only
 SAS computed → terminal: "Tarayıcı: Chrome · Linux (bid k3f…)  Doğrulama kodu: 482 913  Onaylıyor musunuz? [e/H]"
 user types e  (60 s timeout → no)
 store peer {bid, qB}; macC = HMAC(K, "C" ‖ T)
 ── send k=hs {"t":"pair4","ok":true,"macC"} ───────────────────────────────────────────────────────►
                                                                         verify macC → store device {deviceId, qC}; done
                                                                         then: session handshake (§7.4) + peer.hello / device.info
```
Notes:
- `id(Q)` = lowercase base32(SHA-256(Q_raw))[:16]. `‖` = concatenation of bytes; strings are UTF-8, keys raw 65 bytes, nonces raw.
- **Relay MITM:** substituting `qC` or `qB` changes one side's `T`, so `macB` fails at the device → the code is burnt. Forging `macB`
  without the secret requires the secret, and offline guessing from an observed `macB` costs 2^40 × 600,000 PBKDF2 iterations
  before the 10-minute expiry (and the slot is already burnt). Not feasible.
- **Shoulder-surfed code, attacker races the user:** the device terminal shows the attacker's browser label and a SAS that the
  legitimate user's screen does not show, so the user answers `H`.
- `pair4 {ok:false}` on refusal; the browser shows "Eşleştirme cihazda reddedildi".
- PBKDF2 cost: ~0.3–1 s on phones and in CPython. The UI shows "Doğrulanıyor…".

### 7.4 Session handshake (every WebSocket connection, per browser tab × device)

```
 Browser                                                                  Device
 eB ← ephemeral P-256 (non-extractable), nb ← 16 B
 ── send to <deviceId> k=hs {"t":"hs1","v":1,"bid","eB","nb"} ────────────────►
                                                        reject if bid not in peers / revoked / > 20 hs/h
                                                        eC ← ephemeral, nc ← 16 B
                                                        T  = SHA-256("pixel-hs-v1" ‖ deviceId ‖ bid ‖ QC ‖ QB ‖ eB ‖ eC ‖ nb ‖ nc)
                                                        ikm = ECDH(eC, eB) ‖ ECDH(dC, QB)
                                                        okm = HKDF-SHA256(salt=T, ikm, info="pixel-e2e-v1", L=96)
                                                        k_b2c = okm[0:32], k_c2b = okm[32:64], k_conf = okm[64:96]
                                                        ch = base64url(T[0:12])
 ◄── send to c:<conn> k=hs {"t":"hs2","v":1,"eC","nc","ch","mac":HMAC(k_conf,"C"‖T)} ──
 compute ikm with ECDH(eB, eC) ‖ ECDH(dB, QC), same okm
 verify mac (proves the device holds dC), check ch
 ── send k=hs {"t":"hs3","ch","mac":HMAC(k_conf,"B"‖T)} ─────────────────────►
                                                        verify (proves the browser holds dB) → channel open
 ◄────────────── encrypted traffic, k=e, seq from 0 in each direction ────────►
```
Properties: mutual authentication from static-static ECDH plus key confirmation; forward secrecy from ephemeral-ephemeral ECDH
(the ephemeral keys are discarded after derivation); key separation per direction; the channel id binds the transcript.
Known: key-compromise impersonation if `dC` is stolen (accepted, because that means the device is compromised). On any failure, the device
records `hs.fail` in the audit log and sends nothing back (no error oracle). The browser times out after 10 s and shows
"Cihazla güvenli bağlantı kurulamadı". If its stored device record is the likely cause, it also shows "Yeniden eşleştirmeyi deneyin".

### 7.5 Message encryption (envelope)

- Frame: `{"t":"send","to":…,"ch":"<ch>","seq":<n>,"k":"e","b":"<base64url(ciphertext ‖ tag)>"}`
- `dir` = `"b2c"` (browser → device, key `k_b2c`) or `"c2b"` (key `k_c2b`).
- IV (12 bytes) = 4 zero bytes ‖ uint64_be(seq). Each direction has its own key and its own counter starting at 0, so an IV is never
  reused under a key. At seq = 2^32 the sender must re-handshake (practically never).
- AAD = UTF-8 `"pixel-e2e-v1|" + ch + "|" + dir + "|" + seq`.
- Plaintext = UTF-8 JSON of the inner message, then `0x00` padding to the next multiple of 64 bytes (JSON never contains raw NUL;
  the receiver strips trailing NULs).
- Receiver: requires `seq == expected` (the relay preserves order per socket pair). On mismatch, auth failure or bad JSON: drop
  the message and count a failure; after 3 failures, close the channel.
- Re-handshake: on reconnect, after 24 h, or when either side sees `seq` ≥ 2^32.

### 7.6 Cross-implementation tests (Phase 13, mandatory)

`tests/test_v3_browser.py` drives headless Chrome over CDP (the existing stdlib approach from Phases 4–10):
1. Python generates key pairs, ECDH secrets, HKDF outputs and GCM ciphertexts → the browser's `e2e.js` reproduces and decrypts them;
2. the browser encrypts → Python decrypts;
3. a full pairing + handshake between the real connector process and the real page through `dev_relay`;
4. negative cases: tampered tag, wrong AAD, replayed seq, invalid point from the "relay" (the test acts as the relay), wrong code
   (slot burnt), SAS refusal.

## 8. Engine adapters

```python
class Engine(Protocol):                       # engines/base.py
    name: str                                 # "claude" | "ollama" | "openai"
    def available(self) -> dict               # {"available": bool, "version": str|None, ...} (cached 60 s)
    def start(self, agent, task, prompt: str, events: "TaskEvents") -> "Running"
class Running(Protocol):
    def cancel(self) -> None                  # idempotent, non-blocking; the engine ends with events.end(status="cancelled")
class TaskEvents(Protocol):                   # implemented by tasks.py; thread-safe
    def part(self, part: dict) -> None        # coalesced into task.chunk (§3.5)
    def live(self, **usage) -> None           # inTok/outTok/cacheRead/cacheWrite running counters
    def office(self, state: str, tool: str|None = None, label: str|None = None) -> None
    def end(self, status: str, result: str|None, usage: dict, cost_usd: float|None, cost_basis: str,
            turns: int|None = None, error: dict|None = None, denials: int = 0) -> None
```

### 8.1 Claude Code (`engines/claude.py`)

Facts verified 2026-10-16 in the official docs [S8][S9][S10][S11].

#### 8.1.1 Command line (argv list, no shell)

```
<claude_path> -p
  --output-format stream-json --verbose --include-partial-messages
  --permission-mode <mode> [--permission-prompts none]           # §8.1.3; the flag needs Claude Code ≥ 2.1.259
  [--allowedTools <rule> …] [--disallowedTools <rule> …]
  (--session-id <uuid> | --resume <uuid>)                         # §8.1.5
  [--model <alias-or-id>] --max-turns <n> [--max-budget-usd <x>]
```
- **Prompt on stdin**, not argv (argv is visible to other local users via `ps`, and has length limits). The connector writes the
  prompt UTF-8 to the child's stdin and closes it. `-p` without a prompt argument reads stdin [S8].
- `cwd` = the resolved workspace (§6.4). Environment = the connector's environment minus `PIXEL_OFFICE_*` connector secrets, plus
  `PIXEL_OFFICE_DISABLE=1`. Nothing from the request goes into the environment.
- **No `--bare`** by default: bare mode skips OAuth/keychain, so it would not work with a Claude subscription login [S8]. Config
  `engines.claude.bare: true` (for API-key users) adds `--bare`.
- `claude_path` is resolved once at `install-service` / `setup` with `shutil.which("claude")` and stored in `connector.json`, because
  service managers have a minimal `PATH`.
- Version check at start-up: `claude --version` → parse `x.y.z`. Below **2.1.259** omit `--permission-prompts`. Also read
  `system/init.capabilities` and ignore unknown values.
- Warn in `doctor` and in the UI ("Claude Code bu klasördeki proje ayarlarını çalıştırır"): without `--bare`, `claude -p` runs
  project hooks and `.mcp.json` servers of the workspace **without a trust dialog** [S8]. This is one more reason why only allow-listed
  workspaces are possible.

#### 8.1.2 Auth detection (for honest cost labels)

`claude auth status` (JSON, `authMethod` ∈ `none`, `claude.ai`, `oauth_token`, `api_key`, `api_key_helper`, `third_party`) [S11], once per
connector start and again after a failed run. Mapped to `device.info.engines.claude.auth`: `claude.ai`/`oauth_token` → `subscription`;
`api_key`/`api_key_helper` → `api_key`; else `other`/`unknown`. `system/init.apiKeySource` confirms it per run. **The connector never
reads, copies or transmits any Claude credential.**

#### 8.1.3 Permission profiles (decision)

| Profile (UI label) | Flags | Effect |
|---|---|---|
| `readonly` — "Sadece okuma" | `--permission-mode dontAsk` | Reads inside the working directory and Claude Code's read-only command set. Everything that would prompt is denied [S9]. |
| `edit` — "Düzenleyebilir" (**default**) | `--permission-mode dontAsk --allowedTools Edit Write NotebookEdit` | Plus file edits. Shell commands beyond the read-only set and network fetches are denied. |
| `dev` — "Geliştirici" | as `edit` plus `--allowedTools` entries from `profiles.dev.allow` (e.g. `"Bash(npm test *)"`, `"Bash(pytest *)"`, `"Bash(git status *)"`, `"Bash(git diff *)"`) | Exact, device-defined command prefixes |
| `auto` — "Otomatik" | `--permission-mode auto --permission-prompts none` | Classifier-reviewed autonomy. **Only selectable when `profiles.auto.enabled: true`** in `connector.json`. The UI shows a warning; recommended together with `confirm.task: "always"`. |
| *(none)* | `bypassPermissions` / `--dangerously-skip-permissions` | **Never.** The connector has no code path that emits it. `config-check` rejects any config containing it, and tests grep the argv builder. |

Always added: `--disallowedTools` with the built-in deny rules (deny rules apply in every mode [S9]):
`"Bash(sudo *)" "Read(~/.ssh/**)" "Read(~/.gnupg/**)" "Read(~/.aws/**)" "Read(~/.pixel-office/**)" "Edit(~/.pixel-office/**)" "Read(~/.claude/.credentials.json)"`,
plus `profiles.*.deny` from config. (Phase 13 verifies the exact path-rule syntax against the permissions docs and fixes it here if needed.)
`--permission-prompts none` is passed for every profile when supported, so a run never waits for a host that doesn't exist. Denials
arrive as `system/permission_denied` and are shown in the UI (§8.1.4).

#### 8.1.4 stream-json parsing

One JSON object per stdout line. Lines that are not valid JSON go to the debug log (never to the browser) and are skipped.
Unknown `type`/`subtype` values are ignored (forward compatible). stderr is read on a separate thread, keeping the last 4 KiB for errors.

| Line | Action |
|---|---|
| `{"type":"system","subtype":"init", session_id, model, permissionMode, apiKeySource, claude_code_version, cwd, tools, capabilities?}` | remember `session_id` and `model`; `events.office("thinking")`; part `note` "Model: <model>" |
| `{"type":"stream_event","event":{"type":"message_start","message":{"id","usage":{input_tokens, cache_creation_input_tokens, cache_read_input_tokens, output_tokens}}}, parent_tool_use_id}` | if `parent_tool_use_id` is null and `id` is unseen: add input/cache tokens to the live counters (dedupe by message id [S10]) |
| `stream_event` / `content_block_delta` with `delta.type == "text_delta"` | part `text` (`delta.text`), main loop only (`parent_tool_use_id == null`) |
| `stream_event` / `content_block_delta` with `delta.type == "thinking_delta"` | part `thinking` only if `engines.claude.showThinking` |
| `stream_event` / `message_delta` with `usage.output_tokens` | live output tokens for the current message id (replace, not add: the value is cumulative per message) |
| `{"type":"assistant","message":{"id","content":[…],"usage"}, parent_tool_use_id}` | for each `tool_use` block: part `tool` {name, v = summary}, `events.office("working", tool=name)`. Text blocks are used only if no `text_delta` was seen for that message id (fallback when partial messages are unavailable). Per-step `output_tokens` here is a placeholder, so ignore it [S10]. |
| `{"type":"user","message":{"content":[{"type":"tool_result","tool_use_id","is_error"}]}}` | part `tool_done` {name (from the remembered tool_use id), ok = !is_error}. Tool result **content is not forwarded** in v3 (it can be large and is already summarised by Claude). |
| `{"type":"system","subtype":"permission_denied", tool_name, message}` | part `denied`; counter++ |
| `{"type":"system","subtype":"api_retry", attempt, retry_delay_ms, error}` | part `retry` |
| `{"type":"rate_limit_event","rate_limit_info":{status, resetsAt?, utilization?, errorCode?}}` | store as the device's `claudeLimit` and push `usage`. If `status == "rejected"`: part `note` "Claude kullanım sınırına ulaşıldı" (+ reset time) |
| `{"type":"result", subtype, is_error, num_turns, result?, total_cost_usd, usage, modelUsage, permission_denials, errors?, duration_ms}` | final accounting (§10.2), then `events.end(status = "success" if subtype == "success" and not is_error else "error", result = result, …)`. `error_max_budget_usd` → status `budget`; `error_max_turns` → `error` code `max_turns`. |
| process exits without a `result` line | `events.end("error", error={"code":"engine_exit","message": <last stderr line, ≤ 300>})`, plus `cancelled` if a cancel was requested |

Tool summary `v` (≤ 200 chars, computed on the device): Read/Edit/Write/NotebookEdit → `input.file_path` relative to the workspace;
Grep/Glob → `input.pattern`; Bash → `input.command` truncated to 120 chars; WebFetch → URL host; WebSearch → query (≤ 80);
Agent/Task → `input.description`; other → empty. All of it is E2E. The office status still only carries the tool name (v2 privacy).

#### 8.1.5 Sessions and cancel

- Each agent has a `claudeSession` UUID. On the first task: `--session-id <uuid>`; afterwards: `--resume <uuid>`. `fresh: true`
  or `agent.reset` → a new UUID (the old transcript stays on disk under `~/.claude/projects`, as usual).
- If `--resume` fails because the session isn't found (result error with that message) → retry once with a new `--session-id` and part `note` "Yeni oturum başlatıldı".
- **Cancel:** send `SIGINT` to the child's process group (POSIX: started with `start_new_session=True`). SIGINT ends the turn cleanly and
  records it [S8]. After 5 s: `SIGTERM` (exit 143; Claude Code terminates its Bash children [S8]). After 10 s more: `SIGKILL`.
  Windows: `CREATE_NEW_PROCESS_GROUP` + `CTRL_BREAK_EVENT`, then `terminate()` after 5 s.

### 8.2 Ollama (`engines/ollama.py`)

Facts from the Ollama API docs [S13][S14][S15].
- Base URL from `engines.ollama.url` (default `http://127.0.0.1:11434`, loopback only unless `allowRemote: true`).
- Request: `POST /api/chat`
  `{"model": agent.model, "messages": [system?, …history, {"role":"user","content": prompt}], "stream": true, "keep_alive": cfg.keepAlive ("10m"), "options": {"num_ctx": cfg.numCtx?}}`.
  History = the last `historyMessages` (default 40) entries of `history/<agent>.jsonl`, trimmed further so that the estimated length
  (chars/4) is ≤ 75% of `num_ctx` when set.
- Response: `application/x-ndjson`, one object per line: `message.content` → part `text`; `message.thinking` → part `thinking`
  (if enabled); `message.tool_calls` → ignored (v3 Ollama agents are chat agents without tools; the UI says so).
- Final object (`done: true`): `done_reason`, `prompt_eval_count`, `eval_count`, `prompt_eval_duration`, `eval_duration`,
  `total_duration`, `load_duration` (**nanoseconds**). The API spec lists these on `ChatResponse`. In practice the last streamed
  object carries them, so the adapter reads them if present and otherwise marks usage `estimated: true` with chars/4.
  `inTok = prompt_eval_count`, `outTok = eval_count`, speed = `eval_count / eval_duration × 1e9` tok/s (part `note`).
  Note: with Ollama's prompt cache `prompt_eval_count` counts only the *evaluated* (uncached) prompt tokens.
- Office state: `thinking` until the first content, then `working` with tool `"llm"`, then `idle`.
- After success: append the user and assistant messages to the history file.
- **Cancel:** close the HTTP connection (Ollama stops generating when the client disconnects) → `cancelled`; nothing is appended to history.
- Errors: connection refused → `engine_unavailable` "Ollama çalışmıyor" (and the UI offers the runtime start button, §9); HTTP 404 with
  model not found → `model_not_found`.
- Cost: `costUsd = 0`, `costBasis = "local"`.

### 8.3 OpenAI-compatible servers (`engines/openai_compat.py`): LM Studio, llama.cpp `llama-server`, vLLM, …

- `engines.openai: [{"id":"lmstudio","name":"LM Studio","url":"http://127.0.0.1:1234/v1","apiKeyEnv":null}]`; loopback only unless `allowRemote`.
- `POST {url}/chat/completions` `{"model", "messages", "stream": true, "stream_options": {"include_usage": true}}`; parse SSE
  `data:` lines; `choices[0].delta.content` → part `text`; the final chunk with `usage {prompt_tokens, completion_tokens}` → usage.
  `data: [DONE]` ends. No usage chunk → chars/4 with `estimated: true`.
- Model list for the new-agent dialog: `GET {url}/models` → `data[].id`.
- History, cancel, office state and cost as for Ollama (`costBasis = "local"`). An `apiKeyEnv` (name of an env var on the device)
  lets a remote OpenAI-compatible endpoint be used deliberately. Then `costBasis = "unknown"` (no price table in v3).

## 9. Runtimes and phone remote control

### 9.1 Semantics

A *runtime* is a local AI service or model the user may want to start or stop remotely (Ollama server, a loaded model, LM Studio
server, a llama.cpp server). Each runtime entry in `connector.json` defines:
- **status**: how to observe it (HTTP probe, `systemctl is-active`, or a process check), which never runs anything with side effects;
- **start** / **stop**: argv lists that are executed verbatim (`subprocess.run(argv, shell=False, timeout=30, stdin=DEVNULL)`,
  env = connector env, cwd = home). Exit code and the first 500 characters of stderr are returned (E2E) and audited.

The browser sends only the runtime **id**. Ids not in the file → `runtime_unknown`. No argument from the request is ever appended.

Kinds:
- `service`: generic start/stop/status as configured.
- `ollama`: adds model operations through the HTTP API (no commands): `GET /api/ps` → loaded models (`name`, `size_vram`,
  `expires_at`) [S14]; `GET /api/tags` → installed models; `model.load` = `POST /api/generate {"model": m, "keep_alive": cfg}` without a prompt;
  `model.unload` = `POST /api/generate {"model": m, "keep_alive": 0}` [S15]. Models must be listed in `models` or allowed by
  `allowAnyInstalledModel: true` (must be installed per `/api/tags`; never pulls).
- `openai`: status = `GET {url}/models`; start/stop optional argv.

### 9.2 `connector.json` (complete example; validated by `config.py`, unknown keys → warning)

```json
{
  "v": 1,
```

## 10. Token and cost accounting

### 10.1 What is measured, and what cannot be known

| Quantity | Claude Code | Ollama / OpenAI-compatible |
|---|---|---|
| Input tokens (uncached) | ✅ `modelUsage[*].inputTokens` | ✅ `prompt_eval_count` / `prompt_tokens` (Ollama: only evaluated, uncached tokens) |
| Cache write / read tokens | ✅ `cacheCreationInputTokens` / `cacheReadInputTokens` | — |
| Output tokens | ✅ result-level only (per-step values are placeholders [S10]) | ✅ `eval_count` / `completion_tokens` |
| Cost | ⚠️ `total_cost_usd`: a **client-side estimate** at list prices [S10]. With a subscription it is an *API-equivalent* figure, not money charged. | 0 (local) |
| Subagent usage | ✅ included in `modelUsage` and `total_cost_usd` (`usage` excludes it [S10]) | n/a |
| Claude subscription remaining quota (5-hour/weekly limits) | ❌ **Not knowable.** Only when Claude Code emits `rate_limit_event` do we get `status`, and sometimes `utilization` and `resetsAt` [S11]. Shown verbatim with its timestamp, never extrapolated. | n/a |
| Usage of Claude sessions not started by the connector (your normal terminal sessions) | ❌ not counted in v3 | n/a |
| Live tokens during a task | ✅ approximate: main loop only (message_start/message_delta); reconciled at the end | ✅ final only (Ollama sends counts at the end) |

The UI always labels the Claude cost "≈ $x (API eşdeğeri tahmini)" when `auth == "subscription"`, and "≈ $x (tahmini)" when `api_key`.

### 10.2 Per-task accounting for Claude Code (resume-aware)

Since Claude Code v2.1.277, a resumed session's result reports the **whole session's** totals, including earlier runs [S10]. The
connector therefore keeps, per agent, `claudeSessionCost` and `claudeSessionTokens` (the last seen cumulative totals) and computes:
```
T  = Σ over modelUsage entries: (inputTokens, outputTokens, cacheReadInputTokens, cacheCreationInputTokens, costUSD)
if claude_version ≥ 2.1.277 and the run used --resume and T.costUSD ≥ prev.costUSD (component-wise for tokens):
    task = T − prev
else:
    task = T                                 # fresh session, or older versions that start at zero
prev ← T
costUsd = task.costUSD (prefer the sum of modelUsage[].costUSD; fall back to total_cost_usd delta)
```
If the result is `error_during_execution` with zeroed fields (session crash [S10]), fall back to the summed per-step input/cache
tokens seen live, set `outTok = null`, `estimated: true`, and leave `prev` unchanged.

### 10.3 Ledger (`usage.sqlite`, stdlib `sqlite3`, WAL)

```sql
CREATE TABLE tasks(
  task TEXT PRIMARY KEY, agent TEXT NOT NULL, engine TEXT NOT NULL, model TEXT,
  started_ms INTEGER NOT NULL, ended_ms INTEGER, status TEXT,
  in_tok INTEGER, out_tok INTEGER, cache_read INTEGER, cache_write INTEGER,
  cost_usd REAL, cost_basis TEXT, estimated INTEGER DEFAULT 0,
  prompt_sha TEXT, prompt TEXT,            -- prompt kept for task.get (local only; purge after 30 days, config retainDays)
  result TEXT, bid TEXT);
CREATE INDEX tasks_agent_time ON tasks(agent, started_ms);
```
Period boundaries use the **device's local time zone** (day = local midnight; week = ISO week starting Monday; month = calendar
month). `device.info.tz` tells the UI which zone the numbers refer to.

### 10.4 Budgets and the gauge

```json
{"scope": "device" | "agent:<key>" | "engine:claude|ollama|openai",
 "period": "day" | "week" | "month", "unit": "tokens" | "usd", "limit": <number > 0>,
 "action": "warn" | "block"}
```
- **Token metric** for `unit: "tokens"`: `in + out + cacheWrite + cacheRead × 0.1`. Cache reads are weighted at 0.1 because Claude Code
  re-reads large cached prompts on every step, and raw sums would make budgets meaningless. The weight is shown in the tooltip.
  For local engines this is simply `in + out`.
- `used` = sum over the ledger for the current period; `pct = min(999, round(100 × used / limit))`.
- States: `ok` < 80% ≤ `warn` < 100% ≤ `over`.
- `action: "block"`: `task.start` is rejected with `budget_exceeded` when `over`. For Claude with `unit: "usd"`, every task also gets
  `--max-budget-usd = min(maxBudgetUsdPerTask, limit − used)` (≥ 0.01; if less, reject), so Claude Code enforces the remaining budget itself [S11].
- `action: "warn"`: never blocks; the UI turns the gauge amber/red.
- A gauge is shown only where a budget exists. Without a budget the UI shows raw numbers, not a percentage (a percentage of
  nothing is meaningless). That is the "percentage where it means something" rule.
- `budget.set` from the browser can add, change or delete budgets if `remote.budgetEdit` is true. Budgets set in `connector.json`
  by hand are marked `"locked": true` and cannot be changed remotely.

## 12. Running as a background service (`service.py`)

### 12.1 Linux: systemd user unit (primary)

`pixel-connector install-service` writes `~/.config/systemd/user/pixel-connector.service`, then runs
`systemctl --user daemon-reload && systemctl --user enable pixel-connector && systemctl --user restart pixel-connector`
(Phase 15: `restart` instead of `enable --now`, so re-running the installer replaces a running old version):
```ini
[Unit]
Description=Pixel Office bağlayıcı
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/usr/bin/python3 %h/.pixel-office/connector/pixel-connector.pyz run
Restart=on-failure
RestartSec=5
UMask=0077
NoNewPrivileges=yes
Environment=PYTHONUNBUFFERED=1
# PATH is minimal under systemd; engine paths are absolute in connector.json.

[Install]
WantedBy=default.target
```
- `ExecStart` uses the absolute path of the Python that ran the installer (`sys.executable`).
- To run without being logged in: `loginctl enable-linger $USER` (printed as an optional step; the user decides).
- Logs: `journalctl --user -u pixel-connector`. The connector logs no prompts or outputs at INFO level.
- `uninstall-service`: `disable --now`, remove the unit, `daemon-reload`.

### 12.2 macOS: launchd agent (documented; tested by a friend in Phase 15 if available)

`~/Library/LaunchAgents/tr.pixeloffice.connector.plist` with `ProgramArguments = [python3, ~/.pixel-office/connector/pixel-connector.pyz, run]`,
`RunAtLoad = true`, `KeepAlive = {SuccessfulExit: false}`, `StandardOutPath`/`StandardErrorPath` under `~/.pixel-office/connector/`. Load with
`launchctl bootstrap gui/$(id -u) <plist>`, unload with `launchctl bootout gui/$(id -u)/tr.pixeloffice.connector`. Notifications via `osascript`.
Note: the agent inherits no shell `PATH`, so `claude`/`ollama` paths must be absolute (resolved at setup).

### 12.3 Windows: Task Scheduler (documented)

`schtasks /Create /TN "PixelOffice\Connector" /SC ONLOGON /RL LIMITED /F /TR "\"<pythonw.exe>\" \"%USERPROFILE%\.pixel-office\connector\pixel-connector.pyz\" run"`,
then `schtasks /Run /TN "PixelOffice\Connector"`. No admin rights needed. Restart-on-failure: the connector wraps its main loop and
re-execs itself after crashes (max 5 per 10 min). Remove with `schtasks /Delete /TN "PixelOffice\Connector" /F`. Cancel semantics: §8.1.5.
There is no PowerShell twin of the connector in v3: Windows friends need Python ≥ 3.8 for the connector (the v2 hook client still works without it).

## 14. Threat model

Assets: (A1) the user's machine and files, (A2) prompts and outputs (privacy), (A3) Claude/compute quota and money, (A4) availability,
(A5) the user's Anthropic account standing.

| # | Threat / attacker | Asset | Mitigation | Residual risk |
|---|---|---|---|---|
| T1 | Malicious or compromised **relay** (Cloudflare account, insider) reads traffic | A2 | AES-256-GCM E2E with keys from authenticated ECDH (§7) | Metadata: ids, sizes (64 B padded), timing |
| T2 | Relay **injects or replays** commands | A1 | AEAD with AAD (ch, dir, seq), strict seq, per-connection keys, handshake MACs | None known |
| T3 | Relay **MITMs pairing** | A1, A2 | Code-keyed MACs over the transcript, PBKDF2 600k, one attempt per code, terminal SAS confirmation (§7.3) | 2^-40 online guess per code |

Recommend `confirm.task:"always"` for sensitive machines. Future: WebAuthn-gated keys |
| T5 | Compromised Vercel serves a **malicious connector installer** | A1 | Installer verifies `SHA256SUMS`, the hash is published in README per release, no auto-update | A user who installs during a compromise and doesn't compare the hash is exposed |

| T9 | Room member shoulder-surfs the pairing code and races | A1 | SAS + terminal confirmation shows the foreign browser label; 10-minute code lifetime; one attempt | User must read the prompt |
| T10 | **Prompt injection** via repo content or a web page makes Claude run harmful actions | A1 | Default profile `edit` (no shell), deny rules for secrets dirs, `dontAsk` + `--permission-prompts none` (no silent approval), `auto` opt-in only | Edits inside the workspace remain possible (that is the feature); use git |
| T11 | Malicious repo in an allow-listed workspace (`.claude/settings.json` hooks, `.mcp.json`) executes on `claude -p` without a trust dialog [S8] | A1 | Only explicitly allow-listed workspaces; doctor/UI warning; `profiles.*.bare` option for API-key users | User allow-lists an untrusted repo |
| T12 | **Command injection** via runtime/agent fields | A1 | Runtime = id only, argv from local config, `shell=False`; prompt via stdin; model names validated (`[A-Za-z0-9._:/-]{1,64}`) and passed as a separate argv element; workspace resolution §6.4 | None known |
| T13 | **Path traversal / symlink escape** | A1 | realpath + commonpath, deny list, re-check per task | TOCTOU between check and Claude's own file access (Claude Code enforces its own working-directory rules) |
| T14 | Local attacker (other OS user) reads keys or prompts | A1, A2 | 0700/0600 files, UMask 0077, prompt not in argv, loopback control API with token + Host check | Root or same user = game over (out of scope) |
| T15 | Timing side channels on pure-Python crypto | A2 | Montgomery ladder, bitwise GHASH, compare_digest; remote timing drowned in jitter | Same-machine attacker (see T14) |
| T16 | **XSS** via streamed model output or device names | A1, A2 | `textContent`-only renderer, CSP `script-src 'self'`, no `innerHTML` for device data | None known |
| T17 | Cross-site WebSocket hijacking | A4 | Ticket in subprotocol + `ALLOWED_ORIGINS` check | — |
| T18 | Cost/quota abuse (runaway agent, loops) | A3 | `--max-turns`, `--max-budget-usd`, task timeout, budgets with `block`, concurrency caps, rate limits | Subscription limits are opaque (§10.1) |
| T19 | Free-tier exhaustion (DoS of the relay) | A4 | Per-socket token buckets, room caps, coalescing; daily reset at 00:00 UTC [S1] | A malicious room member can burn the room's share of the daily quota |
| T20 | Protocol downgrade / old clients | A1 | `v` fields, `hello.v`, `hs1.v` must equal 1; unknown versions rejected | — |
| T21 | Device key theft from backups/sync of `~/.pixel-office` | A1 | Documented: exclude the folder from sync; `reset-keys` | — |
| T22 | **Anthropic terms** violation, account action | A5 | Unmodified `claude` binary on the user's own machine, the user's own login, never touching credentials, only the owner's paired browsers can prompt (no sharing) (§18.1) | Policy may change; see the open question |

## 15. Free-tier budget (≈ 5 users, researched 2026-10-16)

### 15.1 Assumptions (deliberately pessimistic)

- 5 users, each with 1.6 devices on average (**8 connectors**, online 24 h) and **2 browsers** (desktop + phone, 10 in total).
- Desktop page with the relay connected 6 h/day, phone 0.5 h/day. Each browser opens ~10 relay connections/day; each connector reconnects ~24×/day.
- **40 connector tasks per user per day** (200/day) with an average streaming time of 3 min. Chunk coalescing gives ≤ 4 msgs/s,
  so ≤ 720 device→relay messages per task. ~5 browser→device messages per task.
- 3 connector agents per user (15) kept in the office by a 20-minute keep-alive.
- v2 usage as in CLOUD.md §12 scaled to 5 viewers, i.e. 30 session-hours/day of hook traffic (half of CLOUD.md's 10-friend case).

### 15.2 Cloudflare (Workers Free + Durable Objects Free)

| Resource (limit) | Formula | /day | % |
|---|---|---|---|
| Worker requests (100,000/day) | WS upgrades: 8 × 24 + 10 × 10 = 292; `/health` ≈ 50 | **≈ 350** | 0.4% |

## 16. Deployment (what the user does by hand)

Prerequisites: the repo is already on GitHub (`github.com/timuryurdakan/Pixel`), and Vercel is already connected to it (v2).
**No Node.js installation is needed on the dev machine.**

### 16.1 Cloudflare account (once)

1. Sign up at `https://dash.cloudflare.com/sign-up` (email + password, verify the email). The Workers Free plan needs **no payment method**.
2. Dashboard → **Workers & Pages**. On first use, choose your `workers.dev` subdomain (e.g. `timur`). Write it down: the relay URL will be
   `https://pixel-relay.<subdomain>.workers.dev`.

### 16.2 Workers Builds (after Phase 12 has pushed `relay/` to `main`)

1. Workers & Pages → **Create application** → **Import a repository** → *Connect GitHub*. In the GitHub dialog, install the
   Cloudflare app **only for the repository `timuryurdakan/Pixel`**.
2. Select the repo. Configure:
   - Project / Worker name: **`pixel-relay`** (must equal `name` in `relay/wrangler.jsonc`, or the build fails [S6]).
   - Production branch: `main`.
   - Root directory (under advanced settings): **`relay`**.
   - Build command: **`npm install --no-audit --no-fund && npm test`** (Workers Builds uses the wrangler version pinned in `relay/package.json` [S6]).
   - Deploy command: **`npx wrangler deploy`** (default).
   - Build watch paths: include `relay/*` (so pushes that touch only `web/` or `api/` don't build) [S6].
3. **Save and Deploy.** The first build creates the Durable Object namespace. Open the build log: `npm test` must report all tests passing.

### 16.3 Secrets and variables

1. Generate once: `python3 -c "import secrets;print(secrets.token_urlsafe(32))"`. This is `RELAY_SECRET`.
2. Cloudflare: Worker `pixel-relay` → **Settings → Variables and Secrets → Add** → Type **Secret**, name `RELAY_SECRET`, value from step 1 →
   Deploy. (Secrets survive later `wrangler deploy` runs. `ALLOWED_ORIGINS` lives in `wrangler.jsonc`, so don't add it in the dashboard: `vars`
   in the config overwrite dashboard values on every deploy.)
3. Vercel: Project → Settings → Environment Variables (Production):
   - `RELAY_SECRET` = **the same value**;
   - `PIXEL_RELAY_URL` = `wss://pixel-relay.<subdomain>.workers.dev`.
4. Run `python3 tools/set_relay_host.py <subdomain>` (rewrites only the CSP `connect-src` in `vercel.json` to
   `'self' wss://pixel-relay.<subdomain>.workers.dev`). Commit and push; Vercel redeploys automatically. The full ordered list
   is in README "Yayına alma kontrol listesi (v3)".
5. Verify:
   - `curl https://pixel-relay.<subdomain>.workers.dev/health` → `{"ok":true,"v":1}`
   - `curl https://pixel-rouge-phi.vercel.app/api/config` → `"relay":{"url":"wss://…","v":1}`
   - `python3 tests/relay_conformance.py --url wss://pixel-relay.<subdomain>.workers.dev --server https://pixel-rouge-phi.vercel.app --room <rid> --key <key>` → all OK

### 16.4 Node.js: not required (decision)

- Worker unit tests run in Cloudflare's build image (Node 22/24 preinstalled [S6]), and a failing test blocks the deploy.
- Protocol behaviour is tested locally against `tools/dev_relay.py` and remotely against the deployed Worker with the same Python suite.
- There are no preview URLs for Workers that implement Durable Objects [S6]. The trial deploys straight to production after local
  tests pass. Rollback: Worker → **Deployments** → previous version → **Rollback**.
- Only someone who wants `wrangler dev` / `wrangler tail` locally needs Node. In that case use a current LTS (e.g. via NodeSource or
  nvm, because Ubuntu's `apt` package may be too old for wrangler 4); `sudo apt install nodejs npm` is **not** part of the required steps.

### 16.5 Per machine (each user)

1. Office → **Cihazlar → Cihaz ekle** → copy and run the install command for your OS (Python ≥ 3.8 required).
2. `pixel-connector pair` → type the code into the browser → compare the SAS → `e`. Repeat on the phone (PWA) with a new code.
3. Optional: `loginctl enable-linger $USER` (Linux, run without login); the polkit rule for Ollama (§9.2); edit `workspaces` and `runtimes`
   in `~/.pixel-office/connector/connector.json`, then `pixel-connector config-check` and `systemctl --user restart pixel-connector`.
4. Remove the resident agents if they are still in the room: `curl -X POST "https://<host>/api/residents?room=<rid>" -H "Authorization: Bearer <key>" -H "Content-Type: application/json" -d '{"residents":[]}'`.

### 16.6 First weeks

Weekly: Cloudflare → Workers & Pages → `pixel-relay` → Metrics and Durable Objects usage (requests, duration); Vercel Usage; Upstash
Usage. Compare with §15. If the DO duration exceeds 50%: raise the coalescing interval (`connector.json → limits.chunkMs`, default 250).

## 18. Risks and open questions

### 18.1 Anthropic usage terms (driving Claude Code from a third-party UI)

What the official page says (read 2026-10-16 [S16]):
- OAuth (subscription) authentication "is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise
  subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications".
- Developers building products "should use API key authentication". Anthropic does not permit third-party developers "to offer Claude.ai
  login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users", nor to
  "collect, store, or intermediate Claude.ai credentials".
- It does **not** prevent "an end user from signing in to the unmodified Claude Code binary with their own Claude subscription".
- "Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK."
- Offering Claude Code inside a product requires the Commercial Terms, an unmodified binary, and that each end user authenticates
  with their own credentials, without the provider paying for, reselling or intermediating usage. Names/logos: you may say in plain
  text that a product runs Claude Code, but you may not use the names in your product name or logo.

Secondary reporting (not authoritative) describes 2026 enforcement against third-party harnesses that used subscription OAuth
tokens directly [S17].

Assessment: v3 runs the **unmodified `claude` binary on the user's own machine, signed in by the user through Anthropic's own flow**. Our software
never sees, stores or forwards a credential, and only the owner's own paired browsers can prompt it. That matches the permitted pattern
("an end user signing in to the unmodified Claude Code binary with their own subscription"), and it is closest to a personal remote
control. The grey zone is "ordinary, individual usage": heavy unattended or automated use through a subscription may not count.

**Safest default (decision):**
1. Each person only drives their own Claude Code with their own login. No sharing of agents with friends (v3 makes this impossible by design).
2. Never touch credentials; never pass `--bare` with subscription logins; never modify or wrap the binary beyond normal CLI flags.
3. Human-initiated tasks only (no schedules, no automations; those are v4 and need this question answered first). Rate limits and budgets are on by default.
4. Plain-text attribution only ("Motor: Claude Code"), no Anthropic names or logos in the product name, icon or branding.
5. The UI shows the auth mode. For any **startup/commercial phase**, switch the recommended setup to **API-key authentication**
   (`claude auth login --console` or `ANTHROPIC_API_KEY` with `engines.claude.bare: true`), which the docs designate for developers'
   products, and contact Anthropic (the docs point to sales) before launch. For phone control of Claude Code only, Anthropic's own
   **Remote Control** (`claude remote-control`) is the first-party alternative and should be mentioned in the README.
- *Open question Q1:* written confirmation from Anthropic that a self-hosted remote UI driving a user's own `claude -p` with their own
  subscription is "ordinary individual use". Owner: the user, before inviting anyone beyond close friends.

## 20. Implementation deviations

### Phase 12 deviations (2026-10-17)

Everything not listed here is implemented as specified in §3, §4, §6.2, §13 and §17.1.

1. **`relay/src/core.js` added.** The room logic (`RoomCore`) and the Worker routing (`handleRequest`) live in `core.js`, written
   against injected interfaces (`ctx`, a `platform` object with `now`, `newPair`, `upgradeResponse`, `autoResponse`). `room.js`
   (`RoomRelay extends DurableObject`) and `index.js` are thin glue. Reason: without Node on the dev machine, the logic must be
   testable in headless Chrome and under `node:test` without `cloudflare:workers`. There are two node:test files
   (`test/lib.test.js`, `test/core.test.js`) plus `test/ticket_vectors.json`.
2. **Frame cap 96 KiB (98,304 bytes), not 64 KiB.** §3.2 allows `b` up to 60 KiB decoded for devices, which is 81,920 base64url
   characters and does not fit in a 64 KiB frame. `welcome.limits.maxFrame` reports 98304; a larger text frame → close 1009.
   The `b` caps are unchanged (browser 48 KiB, device 60 KiB decoded → `err too_large`). Billing is per message, not per byte.
3. **`wrangler.jsonc` uses the legacy migration form** (`"migrations": [{"tag": "v1", "new_sqlite_classes": ["RoomRelay"]}]`), the
   documented fallback of §4.2. The pinned `wrangler` **4.145.0** also accepts `exports` (checked against its `config-schema.json`);
   the migration form is chosen because it is the long-established path for the SQLite free tier and the two are mutually exclusive.
   `compatibility_date` is `2026-09-15` (≥ 2026-04-07 for automatic Close replies, and not newer than the workerd 1.20260930 that
   wrangler 4.145.0 bundles). Added `"workers_dev": true` and `"preview_urls": false` (DO Workers have no preview URLs anyway).
4. **`npm test` = `node --test test/*.test.js`** (explicit glob instead of a bare directory; Node 22+ in the build image).
5. **Unspecified details, now fixed:** 20 consecutive rate-limited frames on one socket → close **4029** (before that each gets
   `err rate_limited`); a binary frame counts as a bad frame (`err bad_frame`); `pair.open` from a device that already holds a slot
   replaces its own slot (still ≤ 1 per device); `pair.close` of a slot the device does not hold → `err slot_unknown`, success is
   silent; a device `hello` re-broadcasts `presence` (so `app` is current); the `{"t":"ping"}` fallback inside the object (if the
   auto-response did not catch it) is answered and not rate-limited; `send` to a `pair:` slot uses both the socket bucket and the
   3/min pairing bucket.
6. **Close code 4001 is reserved, not sent.** An expired ticket is refused before the upgrade (HTTP 401), and open sockets are never
   closed because their ticket expires (§6.2: tickets only gate the upgrade).
7. **Extra HTTP answers:** `405` (wrong method), `426 upgrade_required` (plain GET on the WS path), `503 relay_not_configured` (Worker
   without the `RELAY_SECRET` secret); the DO answers `400 bad_request` if the Worker-set claims header is missing. Bodies are
   `{"error": "<code>"}` with `Cache-Control: no-store`. `X-Pixel-Claims` carries only `{r, ro, id}`.
8. **`/api/config`** always contains `"features"` (`[]` when the relay is off, `["control"]` when on). v1/v2 clients ignore it.
9. **`web/js/relay.js`:** besides `start/stop/send/presence`, it has `need(reason, on)` (keeps the socket while any reason such as
   `'dialog'` or `'task'` is active), `status`, `destroy()`, and injectable `isVisible`, scheduler, `WebSocket` and `fetch` (tests).
   Browsers cannot read the HTTP status of a refused upgrade, so `quota` = two consecutive attempts that end without a `welcome`
   (or with close 4029), or HTTP 429 from `/api/relay_ticket`. Ticket answers 400/401/403/404/503 stop the client (`idle` with
   `{error}`) instead of retrying forever. The ticket URL must be `wss://…/v1/rooms/<rid>/ws` (or `ws://127.0.0.1:…` in dev).
10. **`vercel.json` CSP is unchanged in Phase 12.** §13.5/§19 assign it to Phase 14 and it needs the user's exact workers.dev host; nothing
    in the shipped UI opens a relay socket yet. `dev_server.py --relay` adds the dev relay origin to its own CSP `connect-src`.
11. **`dev_server.py --relay`** also takes `--relay-port` (default 8788, 0 = free port); the dev relay accepts browser Origins of the
    dev server (`http://127.0.0.1:<port>`, `http://localhost:<port>`). `RELAY_SECRET` from the environment is reused if ≥ 32 chars.
12. **Tests beyond §17.1:** `tests/test_relay_js.py` runs `relay/test/*.test.js` (unchanged) and `tests/js/*.test.js` (`relay.js`, the
    Cloudflare glue) in headless Chrome with `node:test`/`node:assert` shims (`tests/js_shims/`) mapped in by an import map;

    the two time-forging tests (expired/future tickets) skip; slot expiry is in-process only.
13. **§9.2 example paths** use `/home/user/…` (the release test forbids personal absolute paths in the repo).

### Phase 13 deviations (2026-10-17)

Everything not listed here is implemented as specified in §5–§10, §12 and §17.2.

1. **Extra files.** `pixel_connector/app.py` holds the `Connector` class (wiring of relay → router → dispatcher →
   scheduler → engines, the inner-message handlers of §3.4, the loopback control routes). Test helpers:
   `tests/_v3_env.py` (dev_relay + dev server + room + a Python `FakeBrowser` that speaks the browser side with the

   `tests/vectors/` also has `hmac.json` (RFC 4231).
2. **Vector subsets.** NIST CAVP GCM: the first 3 vectors of every (PTlen, AADlen) section of `gcmEncryptExtIV256.rsp`
   and `gcmDecrypt256.rsp` with IVlen 96 and Taglen 128 (150 vectors, 34 of them FAIL cases). Wycheproof
   `aes_gcm_test.json`: all 66 cases with keySize 256 / ivSize 96 / tagSize 128 (27 modified tags). Wycheproof
   `ecdh_secp256r1_ecpoint_test.json`: all 355 cases; only uncompressed points are accepted, so the one "acceptable"
   compressed point is rejected too. NIST CAVP ECC CDH P-256: all 25. RFC 5903 §8.1, RFC 5869 A.1–A.3, RFC 7914 §11,
   RFC 4231 (cases 1–4, 6, 7). Sources and the retrieval date are inside each JSON file.
3. **Pairing details fixed (§7.3).** `pair1` also carries `label` (≤ 40, shown in the terminal; informational, not part
   of `T`; what binds is `bid` = id(qB) and the SAS). The slot is burnt (`pair.close`) as soon as the **first** `pair1`
   arrives, so the code really allows one attempt; `pair3` is therefore sent to the device id, not to the slot.
   `pair4` carries `name` (device name) on success and `reason` ∈ `code` | `refused` | `timeout` on failure. The PBKDF2
   password is the 8 normalised secret characters as ASCII. A `pair3` must arrive within 120 s of `pair1`. `seq` of
   `k:"hs"` frames is a per-connection counter that receivers don't check (handshake bodies are self-authenticating).
4. **`ws.py` gained `last_rx`** (time of the last received bytes, pongs included) so the connector can apply the 75 s
   dead-link rule while using protocol pings, which `recv()` otherwise swallows.
5. **Inner messages.** `task.chunk` and `task.end` also carry `agent` (for watching channels). `device.info` also has
   `deviceId`. Agent JSON has `engineId` (the OpenAI-compatible server id); `agent.create` takes an optional `engineId`
   (default: the first configured server). Ollama/OpenAI agents may omit `workspace` (it is then only the office project
   name); Claude agents require one. Results are truncated so the whole inner message fits one frame (56 KiB of JSON)
   instead of "64 KiB of result" (which cannot fit the 60 KiB device `b` cap); `task.get.result` keeps ≤ 40 KiB of
   result and fits the prompt in the rest. Both set `"truncated": true`; the full text stays in the local ledger.
6. **Budgets.** Remote budgets (`budget.set`) are stored in `budgets.json`; per-agent budgets live on the agent record
   and are changed with `agent.update` (`budget.set` with an `agent:` scope → `not_allowed`). The Claude
   `--max-budget-usd` cap is floored to cents so it never exceeds the remaining budget; below 0.01 the task is refused.
7. **`connector.json` additions (all optional):** `engines.claude.cancelGraceS` / `cancelTermS` (5 / 10 s),

   `handshakesPerHour`, runtime status `{"systemd": unit, "user": bool}` and `{"process": name}` besides `{"http": url}`.
   Any key or value matching `bypass permissions` / `dangerously` / `skip-permissions` (case-insensitive) anywhere is a
   validation error.
8. **Office presence.** A subclass of `pixel_agent.Sender` with the 20-minute keep-alive; ages are clamped to the
   server validator's limits (`stateAgeMs` ≤ 24 h, `startedAgeMs` ≤ 7 days) so a long-idle agent's keep-alive is never
   rejected. v2's coalescing rules stay as they are, so a label change within the same state group (e.g. idle
   "Hazır" → idle "Görev bitti" after a sub-second task) can take up to 30 s to show. Labels: "Hazır" after creation,
   "Onay bekliyor", "Görev bitti", "Hata", "Durduruldu", "Reddedildi", "Bütçe doldu", "Süre aşımı".
9. **Claude Code facts checked against the bundled CLI 2.1.301 (`--help`, `--version` and `auth status` only, with a
   temp HOME) and the docs (2026-10-17):** `--permission-prompts none` exists (≥ 2.1.259); `--permission-mode` choices
   are `acceptEdits, auto, bypassPermissions, manual, dontAsk, plan`; `--allowedTools` / `--disallowedTools` take
   space-separated rules; `claude auth status` prints JSON with `authMethod`. The deny-rule syntax `Read(~/.ssh/**)`
   (home-anchored `~/`) is correct per the permissions docs. `rate_limit_event.resetsAt` has no documented unit, so
   seconds and milliseconds are both accepted. Live counters are approximate (a message's placeholder `output_tokens`
   from `message_start` stays until a `message_delta` replaces it); the final numbers come from `result.modelUsage`. A
   resumed session that no longer exists is detected from "No conversation found…" in stderr or `result.errors`.
10. **Approval page.** The page is opened with the link that `pixel-connector approve --link` prints
    (`/onay?t=<token>` sets an HttpOnly, SameSite=Strict cookie and redirects); forms carry a CSRF token derived from the
    control token; `Host` must be `127.0.0.1:<port>` or `localhost:<port>`; CSP `default-src 'none'`. Control API routes:

### Phase 15 findings and deviations (2026-10-19)

Security review of relay/, pixel_cloud/relay.py, tools/dev_relay.py, pixel_connector/, web/connector/, the v3 web modules,
vercel.json and sw.js, line by line for crypto.py, session.py and e2e.js. Regression tests for every fix are in
`tests/test_phase15_security.py` (plus the extended canaries in `tests/test_connector_tasks.py`, the CSP tests in
`tests/test_release.py` and `tests/js/relay_client.test.js`). After the fixes: **467 tests, all pass (1 skipped: no `pwsh`)**.
No critical or high finding remains open.

**Fixed**

| # | Severity | Finding | Fix |
|---|---|---|---|
| F1 | Medium | The `/onay` cookie held the full control token. Browsers send `127.0.0.1` cookies to **every** local port, so any other local web server the user's browser talks to (e.g. an untrusted project's dev server) received a token that also unlocks `/ctl/*`, including `pair/start` + `pair/confirm` (pair a foreign browser = remote control). | A separate page token `HMAC(token, "pixel-onay-page")[:32]` is the only thing `/onay?t=` and the cookie accept; the cookie is `Path=/onay`; `/ctl/*` accepts only the control token. `approve --link` prints the page link. |
| F2 | Medium | `install.sh` under `curl … \| sh`: a truncated download runs the lines that arrived; `--server http://…` was accepted (a network attacker could swap both the `.pyz` and `SHA256SUMS`); the `pixel-connector` shim was written with a heredoc that interpolated `$PY` / paths unquoted. | Whole script in `main()` called on the last line; `--server` must be `https://` (or `http://127.0.0.1`/`localhost` for tests); the shim quotes with a POSIX `sq()` helper. |
| F3 | Medium | Re-running the installer (the documented update path) left the **old** connector running: `systemctl --user enable --now` is a no-op for a running unit; `launchctl bootstrap` fails while loaded; `schtasks /Run` doesn't replace a running instance. A security update would not take effect until reboot. `$` in `ExecStart` paths was environment-expanded by systemd. | Linux: `daemon-reload` → `enable` → `restart`; macOS: `bootout` (ignored) → `bootstrap`; Windows: `/Create /F` → `/End` (ignored) → `/Run`. `_quote_systemd` doubles `$`. §12.1 updated. |
| F4 | Low | The connector followed any `url` from the ticket answer; a `ws://` URL would send the relay ticket in clear text. | `relay.fetch_ticket` accepts only `wss://host[:port]` or `ws://127.0.0.1[:port]` with the path `/v1/rooms/<own room>/ws` (same rule as `relay.js`). |
| F5 | Low | Claude Code's child environment kept server secrets a developer may have exported in the same shell (`RELAY_SECRET`, `PIXEL_SECRET`, Upstash tokens); a prompt-injected run with a shell (`dev`/`auto` profile) could read them. | `child_env` drops `PIXEL_*`, `UPSTASH_*`, `KV_REST_*` and `RELAY_SECRET` (and still sets `PIXEL_OFFICE_DISABLE=1`). |
| F6 | Low | `pixel-connector approve` printed the remote-supplied agent name, title and prompt preview raw: terminal escape sequences from a paired (or compromised-origin) browser reached the user's terminal. | `term_safe()` replaces non-printable characters before printing. |
| F7 | Low | `install.ps1` had non-ASCII strings; Windows PowerShell 5.1 reads BOM-less scripts as ANSI (garbled messages); it assigned the automatic variable `$args`; no scheme check on `-Server`. | ASCII only (like `web/hook/install.ps1`), `$pyArgs`, `-Server` must be `https://` (or loopback http). |
| F8 | Config | The CSP still named the example host `wss://pixel-relay.timur.workers.dev`; a mismatch with `PIXEL_RELAY_URL` silently breaks v3 (the browser blocks the socket, the client retried forever and showed "quota"). | CSP decision below: `tools/set_relay_host.py` + CSP-violation detection in `relay.js` (status `idle` with `{error:'csp'}`, Turkish notice and a "CSP" label on the devices page). |
| F9 | Test | `relay_conformance.test_pairing_slots` raced `pair.close` (silent on success) against the browser's next `send`; it failed under load (seen in the first full run). The same suite runs against the deployed Worker. | The test now waits for an in-order reply on the same device socket before the browser sends. |

**CSP decision.** Vercel serves `vercel.json` `headers` as static values; environment variables are not substituted there, and there
is no build step. Alternatives considered: serving the HTML entry from a Python function that adds the CSP from `PIXEL_RELAY_URL`
(a function invocation and cold start on every page load, the static `/(.*)` CSP would also apply and browsers enforce both, and
the service worker/offline shell would depend on a function); Vercel Routing Middleware (needs JS + a dependency, i.e. Node in
the build); a `*.workers.dev` wildcard (allows connections to any Cloudflare Worker, including an attacker's, from an XSS). Chosen:
keep the CSP static with exactly one relay host, set by **one validated command** `python3 tools/set_relay_host.py <subdomain>`
(or a `wss://` URL for a custom domain; rejects wildcards, paths and non-`wss` schemes, rewrites only `connect-src`, idempotent),
committed and pushed with the rest. A release test asserts that `connect-src` is `'self'` plus exactly one `wss://` host and no
`*`. If the host and `PIXEL_RELAY_URL` still differ, the browser reports a `securitypolicyviolation`; `relay.js` stops (no retry
storm) and the devices page says "Röle: güvenlik politikası (CSP) röle adresini engelliyor".
